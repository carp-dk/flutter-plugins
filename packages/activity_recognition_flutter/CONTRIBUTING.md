## Getting Started

### Prerequisites

- **Flutter SDK**: >=3.3.0
- **Dart SDK**: ^3.9.2

### Setup Development Environment

1. **Clone the repository**:
   ```bash
   git clone https://github.com/cph-cachet/flutter-plugins.git
   cd flutter-plugins/packages/activity_recognition_flutter
   ```

2. **Install dependencies**:
   ```bash
   flutter pub get
   ```

3. **Set up the example app**:
   ```bash
   cd example
   flutter pub get
   ```

4. **Run the example**:
   ```bash
   # Android
   flutter run -d <android-device-id>
   
   # iOS
   flutter run -d <ios-device-id>
   ```

## Architecture Overview

This plugin uses **Pigeon** for type-safe communication between Flutter and native platforms. Pigeon generates platform-specific code from a single API definition file, ensuring type safety and reducing boilerplate.

### Communication Pattern

```
┌─────────────────────────────────────────────────────────────┐
│                     Flutter (Dart)                          │
│                                                             │
│        ActivityRecognition (Public API)                     │
│         │                          │                        │
│         │ implements               │ uses                   │
│         ▼                          ▼                        │
│  ActivityRecognitionFlutterApi   ActivityRecognitionHostApi │
│  (receives from native)          (calls to native)          │
└─────────────────────────────────────────────────────────────┘
          │                          │
          │ Pigeon                   │ Pigeon
          │ Generated                │ Generated
          │ Code                     │ Code
          ▼                          ▼
┌─────────────────────────────────────────────────────────────┐
│              Native Platform (Kotlin/Swift)                 │
│                                                             │
│       ActivityRecognitionFlutterPlugin                      │
│         │                          │                        │
│         │ implements               │ uses                   │
│         ▼                          ▼                        │
│  ActivityRecognitionHostApi    ActivityRecognitionFlutterApi│
│  (handles Flutter calls)       (calls to Flutter)           │
│         │                                                   │
│         ▼                                                   │
│  Platform APIs                                              │
│  - Android: Google Play Services Activity Recognition       │
│  - iOS: CoreMotion (CMMotionActivityManager)                │
└─────────────────────────────────────────────────────────────┘
```

### Key Components

#### 1. **API Definition** (`pigeons/activity_recognition_api.dart`)
- Single source of truth for the communication interface
- Defines data types, enums, and method signatures
- Used by Pigeon to generate platform-specific code

#### 2. **Generated Code** (Auto-generated by Pigeon)
- **Dart**: `lib/activity_recognition_pigeon.dart`
- **Kotlin**: `android/src/main/kotlin/.../ActivityRecognitionPigeon.kt`
- **Swift**: `ios/.../ActivityRecognitionPigeon.swift`
- **Never edit these files manually** - they are regenerated when the API changes

#### 3. **Dart Implementation** (`lib/activity_recognition_flutter.dart`)
- Public API that developers use
- Implements `ActivityRecognitionFlutterApi` to receive updates from native
- Uses `ActivityRecognitionHostApi` to call native methods
- Converts between Pigeon types and domain types
- Provides reactive streams via `StreamController`

#### 4. **Android Implementation** (`android/src/main/kotlin/...`)

**Main Plugin** (`ActivityRecognitionFlutterPlugin.kt`):
- Implements `ActivityRecognitionHostApi` interface
- Manages activity recognition lifecycle
- Handles foreground service setup
- Converts between Google Play Services types and Pigeon types

**Supporting Classes**:
- `ActivityRecognizedBroadcastReceiver.kt`: Receives activity updates from Google Play Services
- `ActivityRecognizedService.kt`: Processes activity updates and stores in SharedPreferences
- `ForegroundService.kt`: Manages Android foreground service for background tracking

**Flow**:
1. Flutter calls `startActivityUpdates()` via Pigeon
2. Plugin registers with Google Play Services Activity Recognition
3. Activity updates received via BroadcastReceiver
4. Updates processed by JobIntentService
5. Stored in SharedPreferences
6. Plugin observes SharedPreferences changes
7. Converts to Pigeon types and sends to Flutter

#### 5. **iOS Implementation** (`ios/.../ActivityRecognitionFlutterPlugin.swift`)

**Main Plugin**:
- Implements `ActivityRecognitionHostApi` protocol
- Uses CoreMotion's `CMMotionActivityManager`
- Directly sends updates to Flutter without intermediate storage

**Flow**:
1. Flutter calls `startActivityUpdates()` via Pigeon
2. Plugin starts CoreMotion activity updates
3. Activity updates received in operation queue
4. Immediately converts to Pigeon types
5. Sends to Flutter via `ActivityRecognitionFlutterApi`

## Development Workflow

### Modifying the API

When you need to change the communication interface between Flutter and native platforms:

1. **Edit the API definition**:
   ```bash
   # Edit pigeons/activity_recognition_api.dart
   nano pigeons/activity_recognition_api.dart
   ```

2. **Regenerate Pigeon code**:
   ```bash
   dart run pigeon --input pigeons/activity_recognition_api.dart
   ```
   
   This regenerates:
   - `lib/activity_recognition_pigeon.dart`
   - `android/.../ActivityRecognitionPigeon.kt`
   - `ios/.../ActivityRecognitionPigeon.swift`

3. **Update implementations**:
   - Update `lib/activity_recognition_flutter.dart` if needed
   - Update `android/.../ActivityRecognitionFlutterPlugin.kt` if needed
   - Update `ios/.../ActivityRecognitionFlutterPlugin.swift` if needed

4. **Test the changes** on both platforms

### Adding a New Method

Example: Adding a method to get the current activity synchronously

1. **Add to API definition** (`pigeons/activity_recognition_api.dart`):
   ```dart
   @HostApi()
   abstract class ActivityRecognitionHostApi {
     // Existing methods...
     
     /// Get the most recent activity without starting updates
     ActivityEventData? getCurrentActivity();
   }
   ```

2. **Regenerate code**:
   ```bash
   dart run pigeon --input pigeons/activity_recognition_api.dart
   ```

3. **Implement in Kotlin** (`ActivityRecognitionFlutterPlugin.kt`):
   ```kotlin
   override fun getCurrentActivity(): ActivityEventData? {
       // Implementation
       return null
   }
   ```

4. **Implement in Swift** (`ActivityRecognitionFlutterPlugin.swift`):
   ```swift
   func getCurrentActivity() throws -> ActivityEventData? {
       // Implementation
       return nil
   }
   ```

5. **Update Dart API** if needed to expose it:
   ```dart
   Future<ActivityEvent?> getCurrentActivity() async {
       final data = await _hostApi.getCurrentActivity();
       // Convert and return
   }
   ```

### Adding a New Data Type

Example: Adding metadata to activity events

1. **Add to API definition**:
   ```dart
   class ActivityMetadata {
       final String source;
       final double accuracy;
       
       ActivityMetadata({
           required this.source,
           required this.accuracy,
       });
   }
   
   class ActivityEventData {
       final ActivityTypeData type;
       final int confidence;
       final int timestamp;
       final ActivityMetadata? metadata; // New field
       
       // Constructor...
   }
   ```

2. **Regenerate and update implementations** as above

## Making Changes

### 1. Fork and Branch

```bash
# Fork the repository on GitHub
# Clone your fork
git clone https://github.com/YOUR_USERNAME/flutter-plugins.git
cd flutter-plugins/packages/activity_recognition_flutter

# Create a feature branch
git checkout -b feature/your-feature-name
```

### 2. Make Your Changes

- Follow the existing code style
- Add comments for complex logic
- Update documentation if needed
- Add tests for new functionality

### 3. Commit Your Changes

```bash
git add .
git commit -m "feat: add descriptive commit message"
```

**Commit message format**:
- `feat:` - New feature
- `fix:` - Bug fix
- `docs:` - Documentation changes
- `refactor:` - Code refactoring
- `test:` - Adding tests
- `chore:` - Maintenance tasks

- [ ] Activity types are correctly identified
- [ ] Confidence levels are reasonable

## Code Style

### Dart

Follow the [Effective Dart](https://dart.dev/guides/language/effective-dart) guidelines:

```dart
// Good
class ActivityRecognition {
  final ActivityRecognitionHostApi _hostApi;
  
  Future<void> startTracking() async {
    await _hostApi.startActivityUpdates(config);
  }
}

// Use descriptive names
// Use final for immutable fields
// Use async/await for asynchronous code
```

### Kotlin

Follow [Kotlin Coding Conventions](https://kotlinlang.org/docs/coding-conventions.html):

```kotlin
// Good
class ActivityRecognitionFlutterPlugin : FlutterPlugin, ActivityRecognitionHostApi {
    private var flutterApi: ActivityRecognitionFlutterApi? = null
    
    override fun startActivityUpdates(config: ActivityRecognitionConfig) {
        // Implementation
    }
}

// Use camelCase for variables
// Use nullable types appropriately
// Add proper error handling
```

### Swift

Follow [Swift API Design Guidelines](https://swift.org/documentation/api-design-guidelines/):

```swift
// Good
class ActivityRecognitionFlutterPlugin: NSObject, FlutterPlugin, ActivityRecognitionHostApi {
    private var flutterApi: ActivityRecognitionFlutterApi?
    
    func startActivityUpdates(config: ActivityRecognitionConfig) throws {
        // Implementation
    }
}

// Use clear, descriptive names
// Prefer structs over classes when appropriate
// Use proper error handling with throws
```

## Communication

### Getting Help

- **Issues**: Check [existing issues](https://github.com/cph-cachet/flutter-plugins/issues) or create a new one
- **Discussions**: Use GitHub Discussions for questions
- **Documentation**: Read the documentation files in this repository

### Reporting Bugs

When reporting a bug, include:

1. **Description**: Clear description of the issue
2. **Steps to reproduce**: Detailed steps to recreate the bug
3. **Expected behavior**: What should happen
4. **Actual behavior**: What actually happens
5. **Environment**:
   - Flutter version (`flutter --version`)
   - Plugin version
   - Device/Emulator details
   - OS version (Android/iOS)
6. **Logs**: Relevant error messages or logs
7. **Screenshots**: If applicable

### Suggesting Features

When suggesting a feature:

1. **Use case**: Explain why this feature is needed
2. **Description**: Detailed description of the feature
3. **API proposal**: How should the API look?
4. **Alternatives**: What alternatives have you considered?
5. **Additional context**: Any other relevant information
